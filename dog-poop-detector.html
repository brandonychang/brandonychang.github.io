Side project / Real-time computer vision

Dog PoopDetector

A deliberately specific computer-vision product: detect a behavior, preserve proof, and notify the user before the moment disappears.

Role
End-to-end product definition
Scope
Detection requirements · event logic · capture · alerts
Measures
Precision · recall · latency · false-positive rate

The trigger

A recurring problem outside my USC apartment needed evidence, not another vague complaint.

01

From annoyance to product brief

The system needed to distinguish one short behavior from ordinary movement, keep a useful video clip, and deliver it to a phone. A generic dog detector would create constant noise. The target was an event, not an object.

I translated the user story into four requirements: identify the relevant posture, confirm it persists long enough to count, capture the surrounding footage, and send an alert with enough context for a person to act.

02

Define the event

Observable signal

Posture plus duration

Keypoint relationships describe the crouch. A time threshold separates a true event from sitting, stretching, or a single noisy frame.

03

Camera-to-alert workflow

  1. 01

    Observe the scene

    A fixed camera supplies continuous footage of the problem area.

  2. 02

    Estimate pose

    Annotated body and tail keypoints support a posture classifier tuned to the event.

  3. 03

    Confirm and capture

    State logic waits for sustained evidence, then preserves footage around the event.

  4. 04

    Notify

    A mobile alert delivers a thumbnail and clip link for review.

04

The real product tradeoffs

DecisionToo sensitiveToo conservative
Posture thresholdAlerts on sitting or stretchingMisses unusual body shapes
DurationConfirms noisy framesNotification arrives late
Model sizeLower accuracy on edge casesSlower real-time inference
Clip lengthInsufficient contextLarger storage and upload cost
05

How I would evaluate it

Precision

Is an alert real?

Protect the user from alert fatigue.

Recall

Was an event missed?

Measure coverage of the behavior.

Latency

How fast is the alert?

Keep the notification operationally useful.

Error analysis

Where does it fail?

Segment by light, occlusion, breed, angle, and similar poses.

The evaluation plan turns model errors into a product roadmap. A false alert and a missed event create different user costs, so one accuracy score would hide the decisions that matter.
