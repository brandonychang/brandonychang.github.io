USC / Applied AI product

USC ParkingIntelligence

A multimodal retrieval concept that turns traffic documents, live conditions, maps, and route context into one parking decision.

Role
Product design · applied machine learning
Scope
Retrieval · maps · live conditions · recommendations
Stack
FAISS · language models · document and route data

User question

Where should I park for this destination, under the conditions that exist right now?

01

One decision, scattered evidence

A parking recommendation depends on more than distance. Traffic instructions, facility rules, current route conditions, maps, and the user's destination live in separate sources. A traditional search experience returns fragments and leaves the user to reconcile them.

The product brief centered on decision support. Retrieve the relevant evidence, combine it with current context, and present a recommendation a driver understands quickly.

Retrieval before recommendation

  1. 01

    Interpret the trip

  2. 02

    Retrieve policy context

    Use FAISS to find the passages that apply to the location and situation.

  3. 03

    Join current signals

    Pair document context with live traffic and map information.

  4. 04

    Compose the decision card

    Return a primary choice, route rationale, alternatives, and visible source context.

The interface should distinguish retrieved facts from model synthesis. A user needs to know which rule, traffic signal, or map relationship shaped the recommendation, especially when live conditions change.

05

Limits and next tests

Freshness

Conditions expire

Show the time of each live signal and degrade gracefully when a source becomes stale.

Uncertainty

Availability is not guaranteed

Frame recommendations as informed choices and keep an alternative visible.

Trust

Rules need provenance

Expose source context for restrictions, closures, and eligibility.

Evaluation

Test the decision

Measure relevance, route usefulness, freshness, and whether users change the recommendation.
